# Component Pieces for a Bug-Triage Skill — Research Findings

Research date: 2026-08-19. Researcher: b0tts-researcher leaf agent (deepseek-v4-flash).
Goal: find open-source component pieces (any harness/format) that a full bug-triage skill could be assembled from: (1) quick Q&A → shared understanding, (2) agent writes structured bug doc, (3) agent investigates codebase → writes suspected cause into the doc.

## What was searched

- **Stage coverage**: all three stages searched with multiple query angles each (see per-stage query lists below).
- **Query angles used**:
  - Stage 1: "agent skill clarifying questions interview SKILL.md github", "socratic questioning agent skill github", "clarifying questions skill claude code github requirements elicitation", "grill me OR interview skill agent github clarifying questions before coding", "agentskills.io registry skill".
  - Stage 2: "bug report template markdown github issue template", "claude skill bug report template agent", "bug report agent skill SKILL.md template issue write-up", "FAB format action behavior bug report template open source", skills.sh registry API search `q=bug report`.
  - Stage 3: "root cause analysis skill agent debugging github", "git bisect agent skill github debugging reproduction skill claude", "skills.sh OR agentskills.io bug report skill".
- **Platforms**: SearXNG (primary, flaky — several queries returned empty and were retried/refalled), websearch/Exa (fallback), skills.sh registry API (https://www.skills.sh/api/search), skills.sh skill pages, GitHub raw file fetches, GitHub API (repo contents listing), skillsmp.com, eliteai.tools, agentskills.io spec.
- **Verification discipline**: every candidate below was either read in full (raw SKILL.md / skills.sh download API / skills.sh page) or read via substantial search-result excerpts; snippet-only items are explicitly marked. GitHub HTML pages did not extract well via url-read (nav boilerplate) — raw.githubusercontent.com and the skills.sh download API worked reliably.
- **Dead ends**: "FAB (Format-Action-Behavior)" template — no canonical open-source template found; the acronym collides with "Floating Action Button" (e.g. AZgeekster/Bug-Fab is an in-app FAB widget, not a template). SearXNG returned empty for several quoted queries (instance flakiness, not a real "no results" signal).

## Best combinable set

One strong candidate per stage, stitched into the full flow (Q&A → bug doc → investigate → suspected cause in doc):

1. **Stage 1 — citadel `grill` (sethgammon)** — https://github.com/sethgammon/citadel/blob/main/skills/grill/SKILL.md (MIT). One question at a time with a recommended answer, repo-first exploration, ends with a consumable summary block. Rationale: it is explicitly a *discipline* other skills call instead of re-inventing interviews; its "answer from the repo anything the repo can answer" rule keeps the Q&A quick, which is exactly the target flow's "quick Q&A → shared understanding". Alternative if richer artifacts are wanted: nicobailon/grill-for-unknowns (unknowns taxonomy + launch packet + CONTEXT.md).
2. **Stage 2 — ce-report-bug (everyinc/compound-engineering-plugin)** — https://www.skills.sh/everyinc/compound-engineering-plugin/ce-report-bug. Already assembles structured Q&A → environment collection → formatted bug report → issue creation; steal its 6-question set and report format. Pair with microsoft/skills `github-issue-creator` for the "extract structure from chaos" writing discipline and warpdotdev/oz-skills `github-bug-report-triage` (MIT) as the actionability gate + bundled fallback ISSUE_TEMPLATE.md. Add a "Suspected cause" field (per Crosscheck template) to the doc skeleton so stage 3 has a slot to fill.
3. **Stage 3 — debug-agent (millionco)** — https://github.com/millionco/debug-agent/blob/main/.agents/skills/debug-agent/SKILL.md. Hypothesis → instrument → reproduce → evidence-cited root cause, with a hard rule to never claim a cause without runtime evidence. Rationale: it produces exactly the "suspected cause with cited evidence" that gets written into the doc, and its CONFIRMED/REJECTED/INCONCLUSIVE verdict format maps cleanly to a doc field. Lighter alternative: majiayu000 `debug-root-cause-analysis` (no external server); repro-first alternative: silkyland `reproduce-my-bug` (REPRO.md dossier).
