# Research: OBS Fullscreen Source Projector → HDMI Capture Card (Two-PC) — Quality, Latency, and Long-Session FPS Degradation

**Task:** Determine whether OBS Studio's Fullscreen Projector feeding a physical HDMI capture card in a two-PC setup causes quality loss, latency, or efficiency problems vs. Windows display duplication/extension; and whether "projected feed FPS decreases over time in long sessions" has technical basis.

**Date:** 2026-02-12 (session-relative; sources range 2019–2026, with OBS 28–32.x era most relevant)

---

## Summary

The OBS Fullscreen Projector method is the **documented standard best practice** for feeding a capture card from a gaming PC — the official Moonlight capture-card guide calls it "the **recommended** capture card setup" — precisely because it decouples the gaming monitor's resolution/refresh from what the capture card receives; Windows Duplicate instead forces both displays to the lowest common resolution/refresh mode. The projector path involves **zero video recompression** (no NVENC/x264; it is a GPU composited present to a borderless window on the capture card's display), so at matching resolution/refresh it is effectively clean, encoding-free GPU output — with the same color-range/format conversions any display output (including a clone) would have. It adds only ~1 vsync of the projector display (~16.7 ms @60 Hz worst case, present call itself ~50–60 µs) plus the capture card's own latency, which dominates either way. "FPS decreases over time" is a **plausible, documented phenomenon** (multiple OBS GitHub issues report progressive render degradation and projector stutter after ~1–2 hours, usually fixed by restarting OBS), with several known mechanisms — GPU downclocking after idle, refresh-rate mismatch between canvas/display/capture device, render-thread drift, and platform-specific presentation bugs — all of which are diagnosable and fixable. Verdict: **the projector approach is trustworthy for quality and is the correct method; the degradation concern is real but not inherent — it is configurable/fixable.**

## Findings

### Part 1 — Rendering path, resolution, compression, latency, GPU cost

1. **No recompression: the projector is a GPU present, not an encode.** An OBS developer-confirmed forum answer states plainly: "The projector displays the preview in another window, it is **not encoded**" — projecting to a capture card uses no NVENC/x264 on the gaming PC (encoding happens on the stream PC). The frame path is: game capture texture → OBS graphics thread composites → D3D11 present to the projector window on the capture card's display → GPU display engine → HDMI → capture card digitizes. **Severity: n/a (quality fact). Confidence: High.** [OBS Forum — does projecting use NVENC?](https://obsproject.com/forum/threads/with-a-dual-pc-streaming-setup-does-projecting-the-display-outputting-to-streaming-pc-utilise-nvenc-or-not.133970/) | [OBS Backend Design (obs_graphics_thread renders previews + final mix)](https://docs.obsproject.com/backend-design)

2. **Resolution is the display mode's, not the source's.** A fullscreen (source) projector fills the target display; the source is GPU-scaled to the display's mode resolution. If source 1440p → capture display 1080p, the feed is OBS/GPU-downscaled 1080p; if both are 1080p, it is 1:1 with no resampling. Users have reported source projectors looking lower-res than preview projectors when the target display/scaling differs. So "renders at native resolution, bit-perfect" is **approximately true only when the capture-card display mode matches the desired feed resolution**; the Moonlight guide's "Active signal must equal Desktop resolution" verification step exists exactly to catch Windows scaling that would degrade quality. **Severity: Medium (silent quality trap if misconfigured). Confidence: High.** [Moonlight OBS Capture Card Setup Guide](https://guides.moonlight.zip/guides/capture-card/obs-capture-card-setup-guide) | [OBS Forum — Source Projector Lower Resolution than Source?](https://obsproject.com/forum/threads/source-projector-lower-resolution-than-source.156543/)

3. **Color/pixel conversions are identical to any display output — not projector-specific.** The canvas (e.g., NV12 per the Moonlight guide) is converted to RGB for presentation; the HDMI signal carries the display mode's negotiated range (limited/full) and the capture card re-samples it. This is the same conversion a cloned display would undergo. HDR is supported on projectors (OBS 28+; "HDR output in previews and projectors is supported on screens which have EDR support" — macOS notes, and Windows HDR projector support exists for HDR displays). **Severity: Low. Confidence: Medium-High.**

4. **Projectors are vsync'd to the target display and can't exceed its refresh.** OBS's D3D11 projector present path uses the flip model with a waitable object to avoid tearing and avoid stalling the graphics thread (PR #6942, merged for OBS 28.0; tested 120 Hz video on a 60 Hz monitor, Present calls ~50–60 µs). Consequence: **the captured feed is capped at the capture-card display's refresh rate** (60 Hz display = 60 fps feed) regardless of canvas FPS. Mismatch (canvas 240 fps, display 60 Hz) causes frame-pacing/duplication. **Severity: High if refresh mismatch; fix = set capture display to the feed's target refresh. Confidence: High.** [PR #6942 — libobs: Prevent D3D11 projectors from tearing](https://github.com/obsproject/obs-studio/pull/6942)

5. **Latency vs. duplication: projector adds ~1 projector vsync; duplication adds display-engine clone cost — both are dominated by capture-card latency.** Blur Busters' latency-oriented community ranks dual-PC options: passthrough ≈ lowest added latency, display cloning = "slight latency increase," projector ≈ clone (sub-frame to 1 frame). With a 60 Hz projector display the worst-case extra wait is ~16.7 ms; USB capture cards add ~30–60 ms, PCIe ~10–30 ms, so the card dominates. Projector is **not meaningfully worse** than duplication for latency, and it is the only option that preserves the gaming monitor's refresh. **Severity: Low (latency parity). Confidence: Medium** (no instrumented A/B benchmark found; consensus-based). [BlurBusters — best way to stream with lowest input lag](https://forums.blurbusters.com/viewtopic.php?t=13176) | [BlurBusters — cloning vs fullscreen projection (question thread, inconclusive)](https://forums.blurbusters.com/viewtopic.php?f=10&t=13423)

6. **GPU cost is small but real; can conflict when the game already maxes the GPU.** The OBS KB calls projector outputs "incredibly strong and lightweight"; the Moonlight guide still instructs disabling the OBS preview to reduce gaming-PC GPU usage, and known regressions exist (issue #7716: "Since OBS 28 there's less Hz being output to the main monitor if using output projector to another screen" — open). On a GPU already at 95–99% in-game, the extra composite+present per frame can tip into render lag. Also, when the game window has focus, Windows GPU scheduling can starve the OBS render thread — the old but still-cited forum thread "FPS drops on projector even without streaming/recording" (60 → 10–15 fps when the game had focus) demonstrates this contention. **Severity: Medium (efficiency), mitigated by preview disable + GPU headroom. Confidence: High that cost is small, Medium on conflict severity.** [OBS KB — Power of Projectors](https://obsproject.com/kb/power-of-projectors) | [Issue #7716](https://github.com/obsproject/obs-studio/issues/7716) | [OBS Forum — FPS drops on projector when game focused](https://obsproject.com/forum/threads/fps-drops-on-projector-even-without-streaming-recording-in-4k.71046/)

### Part 2 — Known OBS issues relevant to projectors (GitHub + forums)

7. **Tearing on fullscreen projector (Windows 11) — fixed in OBS 28, but re-reported.** Issue #8866 (recurrence of #6936): with old OBS + Windows 11, the fullscreen projector tore constantly for dual-PC capture while the windowed projector did not; the borderless-fullscreen presenter was to blame (removing the title bar only → no tear; removing borders → tear). The fix landed in PR #6942 (D3D11 waitable flip, OBS 28.0). Keep OBS ≥ 28 (ideally current 31/32.x) and current drivers. **Severity: High if on old versions, resolved otherwise. Confidence: High.** [Issue #8866](https://github.com/obsproject/obs-studio/issues/8866) | [PR #6942](https://github.com/obsproject/obs-studio/pull/6942)

8. **"Frame rate drops / stutters after a while" — documented, repeatedly, across platforms:** (a) #12014 (macOS 15, OBS 31): fullscreen projector + Elgato HD60 X / AVerMedia LGE3 stutters massively after ~1 hour; recording is unaffected; "solved if I close and reopen OBS"; (b) #7422 (macOS): frame render time grows 1.5 ms → 6–8 ms over an hour, "something 'leaking' in the rendering process," restart fixes; (c) #13517 (Linux): A/V delay grows over days until seconds, restart clears; (d) #13452: preview projector drops to ~30 fps; (e) Windows: Tom's Hardware thread — game fps drops 100+ → 80 after 1–2 minutes of projecting to a capture card, resolved by matching the capture device's refresh to the output; (f) OBS forum: random dropped frames after ~5 hours of streaming. **Conclusion: progressive degradation reports are real and recurring, but platform/version-specific; none shows a current universal Windows bug. The consistent universal fix is restarting OBS.** **Severity: High (matches user concern). Confidence: High that reports exist; Medium on root cause.** [Issue #12014](https://github.com/obsproject/obs-studio/issues/12014) | [Issue #7422](https://github.com/obsproject/obs-studio/issues/7422) | [Issue #13517](https://github.com/obsproject/obs-studio/issues/13517) | [Issue #13452](https://github.com/obsproject/obs-studio/issues/13452) | [Tom's Hardware — OBS full screen projector dropping frames](https://forums.tomshardware.com/threads/obs-full-screen-projector-dropping-frames.3746539/) | [OBS Forum — dropped frames after hours](https://obsproject.com/forum/threads/random-dropped-frames-after-hours-of-streaming.57397/)

9. **GPU downclocking during idle → frame drops on resume: real mechanism, standard fix.** NVIDIA's own support article documents that "Prefer maximum performance" fixes cases where "the GPU is throttling the clock speeds incorrectly resulting in low fps"; community guidance (NVIDIA/PC-tuning sources) cites downclocking as a micro-stutter source. In a long session, when the projected scene is static (menus, idle screens between games), the GPU drops to 2D/idle clocks; on gameplay resume the first frames exceed render budget → render-lag spikes that read as "the feed got slower after a while." Fix: set NVIDIA Power Management = Prefer Maximum Performance (for OBS or globally), or AMD minimum SCLK; also disable HAGS if it misbehaves (OBS KB lists HAGS as a known source of OBS performance issues). **Severity: Medium-High (most likely Windows-side contributor to the user's perception). Confidence: Medium (strong mechanism, no projector-specific GitHub issue found).** [NVIDIA — Power management mode](https://nvidia.custhelp.com/app/answers/detail/a_id/3130/) | [OBS KB — HAGS](https://obsproject.com/kb/hags)

10. **Memory leaks exist but none is projector-specific in current versions.** Documented leaks: #13446 (recording start/stop leak, closed), #7386 (RTMP source/dest leak, ~100→900 MB over 20 h), #5828 (24/7 streaming OOM-killed after ~24 h). #7422 (macOS) hints at a rendering-side leak affecting projector/preview. No open issue ties a current-Windows fullscreen-projector FPS drop to a RAM leak. A slowly-growing leak could contribute to multi-hour degradation but is not the primary suspect. **Severity: Low-Medium. Confidence: Medium.** [Issue #5828](https://github.com/obsproject/obs-studio/issues/5828) | [Issue #7386](https://github.com/obsproject/obs-studio/issues/7386) | [Issue #13446](https://github.com/obsproject/obs-studio/issues/13446)

11. **Borderless vs "true" fullscreen: not a user choice — OBS projectors are always borderless-fullscreen windows.** There is no exclusive-fullscreen mode for projectors; #8866's AHK experiments confirm the presenter is the borderless window path. This is fine for capture cards (they only see the HDMI signal), and the tearing bug that historically hit this path is fixed in OBS 28+. Relatedly, the Moonlight guide recommends running the game in **borderless windowed** when exclusive-fullscreen games conflict with Game Capture/projector output. **Severity: Low. Confidence: High.** [Issue #8866](https://github.com/obsproject/obs-studio/issues/8866) | [Moonlight guide](https://guides.moonlight.zip/guides/capture-card/obs-capture-card-setup-guide)

### Part 3 — Is the projector the standard best practice?

12. **Yes — it is the officially documented recommendation.** Moonlight's capture-card guide (the reference for two-PC + capture-card setups): "This is the **recommended** capture card setup. It uses OBS Fullscreen Projector to send the game feed to the capture card, which means your gaming resolution and refresh rate are completely independent from what the capture card receives. You can play at 1440p 480Hz while the capture card gets a clean 1080p 240Hz signal… OBS Projector is the recommended method for this reason." r/OBS consensus mirrors this ("full-screen project the program preview to the capture card/monitor. This technique is prevalent in 2 PC streaming setups, over cloning"); the OBS KB endorses projectors generally; capture-card YouTubers push the same (clone "lose[s] the ability to play in HDR and VRR performance could be affected"). **Severity: n/a (consensus). Confidence: High.** [Moonlight — OBS Capture Card Setup Guide](https://guides.moonlight.zip/guides/capture-card/obs-capture-card-setup-guide) | [r/OBS — Passthrough Capture Card or Duplicate Screen?](https://www.reddit.com/r/obs/comments/151abe7/passthrough_capture_card_or_duplicate_screen/) | [OBS KB — Power of Projectors](https://obsproject.com/kb/power-of-projectors) | [Maximize Your Capture Card: OBS Fullscreen Projection Explained](https://www.youtube.com/watch?v=WaSAKaQaCBQ)

13. **Best-practice details that matter (from the Moonlight guide):** use **Fullscreen Projector (Source)** of the Game Capture source — *not* Preview/Program projector (crosshair/centering issues); set Windows display mode to **Extend** (never Duplicate); set the capture-card display to the exact feed resolution/refresh (e.g., 1920×1080 @ 240 Hz or 60 Hz) and verify **Active signal = Desktop resolution**; set OBS canvas = capture resolution and matching FPS; disable the OBS preview to cut GPU usage; run the game borderless-windowed if exclusive fullscreen conflicts. **Severity: High (setup correctness directly determines quality). Confidence: High.** [Moonlight guide](https://guides.moonlight.zip/guides/capture-card/obs-capture-card-setup-guide)

### Part 4 — Extend to a 3rd display vs. Duplicate Monitor 1

14. **Extend + projector is correct; Duplicate is the broken-by-design option for mixed-res/refresh.** Windows clone/Duplicate forces both displays to a single shared mode: "Duplicating forces both displays to the lowest common denominator — this can cap your gaming monitor's refresh rate to whatever the capture card supports" (Moonlight); confirmed by real-world reports — capture card plugged in capped a 144 Hz monitor to 60 Hz ([OBS Forum 72684](https://obsproject.com/forum/threads/game-running-at-only-60hz-while-capture-card-is-set-up.72684/)), and cloning made another user's 144 Hz refresh "variable… not stable. Unusable" ([OBS Forum 153392](https://obsproject.com/forum/threads/dual-pc-streaming-with-144hz-gaming-monitor-capture-card.153392/)). The only clone workaround is forcing a custom high-refresh mode on the capture-card display (Elgato 144 Hz clone method via CRU/custom resolution) — which requires a card that accepts 120/144 Hz input and NVIDIA/CRU gymnastics, and mixed-refresh duplication remains finicky even on Windows 11 (Microsoft Q&A; BlurBusters notes improvements may land with Win11 24H2, still not reliably present). **Extending the desktop and projecting the source onto the capture card's display is the supported, robust pattern — it is exactly what the Moonlight guide and OBS issue #8866 users use.** **Severity: High (architectural). Confidence: High.** [Moonlight guide](https://guides.moonlight.zip/guides/capture-card/obs-capture-card-setup-guide) | [Elgato 144 Hz clone method](https://medium.com/@LtRoyalShrimp_31451/how-to-use-a-144hz-monitor-with-an-elgato-gaming-capture-card-method-1-f432da4a1e8d) | [Microsoft Q&A — duplicate mode mixed refresh](https://learn.microsoft.com/en-us/answers/questions/4062252/setup-2-monitors-with-different-refresh-rate-in-du) | [BlurBusters — different Hz monitors](https://forums.blurbusters.com/viewtopic.php?t=13675)

## Conclusion & Actionable Advice

**Is the projector approach trustworthy for quality?** Yes. Zero recompression; clean HDMI presentation; quality equal to cloning at matching settings, with strictly better flexibility (independent res/refresh, HDR/VRR on the gaming monitor). Two caveats: (1) the capture-card display mode *defines* the feed — a mismatched/scaled mode silently degrades it; (2) it costs a few % GPU and can collide with a maxed-out game GPU.

**Is "FPS decreases over time" plausibly real?** Yes — it is a recurring, documented pattern (GitHub #12014, #7422, #13517, #13452; forum reports), typically manifesting after ~1–2 hours and cleared by restarting OBS. Primary Windows-side mechanisms: GPU downclocking after static-idle periods, refresh mismatch between canvas/projector display/capture device, and (less likely) slow leaks. It is **not** an inherent property of the projector method.

**Is it fixable?** Yes — a checklist, in order of expected impact:
1. Match rates end-to-end: capture-card display mode = desired feed res/refresh (e.g., 1080p@60 or 1080p@240); OBS canvas FPS = that same rate; verify Active = Desktop signal.
2. NVIDIA Control Panel → Power management mode = **Prefer Maximum Performance** (fixes downclock-induced render lag); AMD equivalent: raise minimum SCLK.
3. Use **Fullscreen Projector (Source)** of the Game Capture source (not Preview); disable the OBS preview; run the game borderless-windowed if needed.
4. Keep OBS ≥ 28 (projector flip-model fix) and current GPU drivers; disable HAGS if you see unexplained render lag (OBS KB).
5. Watch OBS Stats: rising **render lag** = GPU/compositor (downclock, contention, or leak) → restart OBS, apply 1–2; rising **skipped frames** = encoder (not applicable to gaming-PC projector); rising **dropped frames** = network (stream PC).
6. Long sessions: restart OBS between sessions/breaks — every documented degradation report clears on restart.

**Is it the correct method?** Yes. Extend desktop + Fullscreen Source Projector onto the capture card is the documented best practice (Moonlight "recommended capture card setup"), replacing both passthrough (limits gaming monitor) and Duplicate (locks gaming monitor to the card's mode). Duplicate Monitor 1 is only acceptable if the capture card shares the monitor's exact res+refresh and you accept the fragile clone path.

## Gaps

1. **No instrumented A/B latency benchmark** (projector vs duplicate, same card) was found; latency comparison rests on consensus + mechanism analysis. Suggested next step: measure with a 240 fps high-speed camera or LDAT-style photodiode on the capture-card output for both methods.
2. **Windows-specific "projector fps drops after hours" root-cause issue** could not be pinned to a single open GitHub issue; evidence is macOS/Linux-heavy. Suggested next step: check OBS Stats (render lag) during the user's long sessions and correlate with GPU clocks (GPU-Z) at the moment degradation starts; open a GitHub issue with logs if reproducible on current OBS.
3. **AMD-specific clone/refresh behavior** and per-card 120/144 Hz input support vary; treat card-specific claims (Elgato/AVerMedia) as indicative.
4. Downclocking link to projectors is mechanistic (static content → idle clocks) rather than documented in a projector-specific issue; confidence Medium.
